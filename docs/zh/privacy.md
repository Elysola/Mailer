# 隐私政策

> 最后更新：2026-11-08
>
> 本中文版仅为便利读者而提供；[英文版](/privacy) 为权威版本。

本政策涵盖 Mailer 软件（下称"本软件"）和本文档站点。它说明本软件处理
什么数据、数据流向何处、以及你对数据有何种控制。

## 摘要

Mailer 是**自托管软件**，不是托管服务。项目方不运营任何接收、存储或
处理你邮件的服务器。你将本软件部署在自己控制的机器上，数据留在那里
——除非你显式配置它把通知内容投递到聊天平台，或显式配置 AI 处理。

没有账号需要注册，没有遥测，没有分析统计。

## 谁负责

自托管 Mailer 时，**你是其所处理邮件的数据控制者**，而 Google 或你
的服务商条款约束邮箱本身。Mailer 项目方无法访问你的邮箱、你的凭据
或你的通知内容。

如果你代表组织评估本软件，该组织是控制者，部署与否是他们的决定，
不是我们的。

## 本软件处理什么

Mailer 连接你指定的 IMAP 邮箱并读取邮件。为了决定是否通知以及发送
什么，它处理：

| 数据 | 原因 | 去向 |
| --- | --- | --- |
| 邮箱凭据——密码，或 OAuth2 客户端凭据与刷新令牌 | 向 IMAP 服务器认证 | 只存于你的主机，在你选择的文件或环境变量中 |
| 邮件头——发件人、收件人、主题、日期、`Message-ID` | 判断消息是否为新、格式化通知 | 保存在本地状态；主题和发件人随通知转发 |
| 邮件正文和附件 | 运行你的解析规则或插件以提取字段（如一次性验证码） | 在内存中使用；只有提取的字段进入通知 |
| OAuth2 访问与刷新令牌 | 无需存储密码即可维持 IMAP 会话 | 写入你配置的 `token_file`，权限 `0600` |

### 本地状态

本软件在你的主机上维护一个 SQLite 数据库（默认 `state.db`）。它保存
最后处理的邮箱游标、用于避免重复通知的 `Message-ID` 集合、以及尚未
送达的通知队列。该队列必然包含未发送通知的主题、发件人、正文文本和
提取的字段。除了你配置的通知之外，这个文件永远不离开你的主机。

### 通知投递

新消息匹配时，本软件向你配置的目标发送通知——包含发件人、主题、
预览或处理后的正文、以及提取的字段：

- **Telegram**，经由 `https://api.telegram.org`
- **Discord**，经由 `https://discord.com/api/v10/...`
- **Slack**，经由你配置的 incoming-webhook URL
- **ntfy** 或 **Gotify**，经由你配置的服务器 URL——可自托管，
  此时一切留在你的基础设施内
- **任意 HTTP 端点**，经由通用 webhook 通知器

这些消息随后经过并由你选择的平台存储，适用其隐私政策。**选择投递
目标就是向第三方披露数据的行为。** 如果你的邮件内容敏感，请相应
选择目标——自托管 ntfy 或 Gotify 让通知留在你自己的基础设施内——
或者不配置通知器运行本软件。

### 可选的 AI 处理

如果你配置了 `llm*` 处理器，消息内容会发送到你配置的 LLM API 端点
——OpenAI 兼容服务商（如 DeepSeek）或 Ollama 本地模型。这**只**对
匹配处理器 `when` 选择器的消息发生，且只有在你显式配置了 LLM 实例
和处理器之后。使用本地模型时，一切不离开你的主机；使用托管服务商时，
服务商的数据政策适用于你发送的内容。本软件本身不做任何 AI 处理，
除非你配置它。

### Google 用户数据

如果你用 OAuth2 连接 Gmail 或 Google Workspace 邮箱，本软件请求
`https://mail.google.com/` scope。该 scope 是通过 IMAP 读邮箱所必需
的，它授予邮箱的完整读写权限。

- 获得的访问与刷新令牌**只**存储于你主机上的 token 文件，权限限制
  为你的用户。
- 本软件使用这些令牌**仅**用于向 Google 的 IMAP 服务器认证，以读取
  你授权的邮箱。不用于任何其他 Google API，也不传输到任何其他地方。
- 你可以随时在 <https://myaccount.google.com/permissions> 吊销访问；
  下一次刷新会失败，本软件会向你告警。

Mailer 对从 Google API 接收的信息的使用遵守
[Google API 服务用户数据政策](https://developers.google.com/terms/api-services-user-data-policy)，
包括 Limited Use 要求。

## 本软件不做什么

- 不发送遥测、指标、崩溃报告或使用统计。
- 不包含分析或广告代码。
- 不读取你配置之外的邮箱或文件。
- 不与 Mailer 项目方或你配置的通知目标、LLM 端点之外的任何方共享数据。
- WebAssembly 插件在沙箱中运行，没有网络、文件系统或环境访问。插件
  接收消息并返回提取的字段；无法外传任何东西。

## 安全

凭据应通过 `password_file`、`client_secret_file` 或环境变量提供，而
非写入 `config.yaml`，这样配置文件可以被分享或提交而不泄露秘密。
token 文件以 `0600` 权限原子写入，且本软件拒绝读取组或他人可读的
token 文件。

OAuth2 授权流程将回调绑定到 `127.0.0.1` 并校验 `state` 参数，防止
无关本地进程或伪造回调注入授权码。

没有系统是绝对安全的。你负责部署主机的安全，包括 token 和状态文件
的磁盘加密。

## 保留与删除

你完全控制保留：

- 删除 token 文件即移除存储的 OAuth2 凭据（同时在 Google 吊销，
  使其无法重用）。
- 删除 `state.db` 即移除游标、去重集合和重试队列。本软件随后会重新
  通知现有邮件。
- 已投递到 Telegram、Discord 或其他平台的消息适用这些服务的保留
  政策，而非本政策。

卸载本软件并删除其配置、token 和状态文件，即移除它在你的主机上存储
的一切。
